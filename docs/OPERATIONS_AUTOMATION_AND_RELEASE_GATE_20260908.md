## 도구 선택

- Chrome + 현재 NOID-B 연결 확장을 먼저 활용한다. 일상적인 수량 계산과 파일 처리에 LLM을 반복 호출하지 않는다.
- 고정된 다운로드·파일 선택·입력 순서는 기존 스크립트 또는 Power Automate Desktop으로 구현할 수 있다. 실제 쿠팡 화면에 대한 호환성 검증 전에는 자동화 완료라고 하지 않는다.
- Claude Code + Claude in Chrome은 다른 도구로 개발·실제 브라우저 검증을 진행할 수 있는 대안이다. 공식 지원 범위는 웹 읽기·클릭·입력·다운로드 및 콘솔 확인이며, 쿠팡의 모든 절차가 지원된다고 보장하지 않는다.
- Brave의 AI browsing은 공식 안내상 early testing 단계다. 실제 발주 운영 자동화의 주 도구로 선택하기 전 검증이 필요하다.
- 새로운 도구 설치·구독·브라우저 교체는 이번 수정에 포함하지 않았다. 로그인 또는 인증이 필요한 외부 단계는 연결 상태 확인 후 진행한다.

## 배포 전 반복 검증 기준

1. 사용자가 신고한 실제 실패를 재현하고 실패 이유를 먼저 확인한다.
2. 양식 없음→다운로드 안내→받은 양식 연결→발주번호 확인을 검증한다. 통신 장애나 손상된 파일을 양식 없음으로 숨기지 않는다.
3. 우편번호 없음→검색 결과 정확 일치→송장 미리보기→실제 XLSX 우편번호 열을 검증한다. 검색 실패가 캐시에 남아 재조회가 막히지 않는지 확인한다.
4. 완료한 발주는 다음 단계에서도 제외되며 원본 이력은 유지되는지 확인한다.
5. UI 테스트에서는 링크·버튼을 실제로 누른다. 1280px와 390px에서 확인한다. API 모의 응답과 실제 외부 시스템 검증 결과는 구분한다.
6. 동일 테스트는 코드로 저장해 재사용한다. 실패, 추가 변경, 미해결 우려가 없으면 같은 검사를 반복하지 않는다.
7. 개발 서버와 프로덕션 빌드를 동시에 실행하지 않는다. 검증을 통과한 변경을 묶어 배포하고 운영 응답을 확인한다.
8. 실제 쿠팡 업로드·주문 전송·영업 데이터 완료 처리는 테스트용으로 실행하지 않는다. 해당 경계가 미검증이면 완료 보고에 명시한다.
