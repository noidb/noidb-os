# 2026-09-08 업무 흐름 수정 계획

사용자가 수정 사항을 모두 전달한 뒤 요청한 작업 범위. 운영 데이터 변경과 배포는 별도 단계다.

## 수용 기준

1. 주간업무에서 SKU 38256624의 거래처 발주 선택 불가 원인을 표시한다. 운영 읽기 확인 결과 단종 상태이므로 임의로 단종을 해제하지 않는다.
2. 쿠폰·광고 등록, 거래처 주문, 재발주요청, 단종 신청을 실제 완료 표시하면 진행 상품·파일 목록에서 제외하고 완료 이력은 보관한다. 파일 다운로드와 완료 저장을 구분한다.
3. 메인 작업 카드에서 직접 출고완료를 저장할 수 있다. Shipment에서 이미 출고한 작업도 메인 진행 목록에서 제외한다. 새로고침과 다른 기기에서도 저장 결과가 유지된다.
4. 피킹에서 단종대기로 이동한 뒤 목록 바로가기를 제공한다. 대기 항목은 누적하여 주간업무 단종 목록과 정확한 SKU 기준으로 함께 처리하고 완료한 항목은 다시 나오지 않게 한다.
5. 두 거래처 발주 버튼의 실제 차이를 확인하고 공통 발주대기 경로를 명확히 안내한다.
6. 거래처 초안의 현재고 0~1개 추가발주 추천 목록을 제거한다.
7. 주간업무 상품 카드의 거래처 주문수량 입력, 수량확인 체크, 추가주문제안 문구를 제거한다. 실제 미입고 수량을 초안에 전달하고 기존 12개 단위 올림 규칙을 적용한다. 기존 초안의 사용자 수정 수량과 거래처는 중복 취합 시 유지한다.
8. 상단 쿠폰 요약의 중복 파일받기 버튼을 제거한다.
9. 앞서 구현한 거래처 발주 취합과 사진 붙여넣기·저장·이미지 출력을 포함해 회귀 검증한다.

## 검증

- 상태 처리·중복 취합·완료 필터와 재시도 단위 검증.
- 개발 서버에서 실제 UI 및 API 모의 데이터로 이동, 완료 후 새로고침, 모바일 폭, 사진 저장과 발주 이미지 생성 확인.
- 타입 검사. 최종 빌드는 개발 서버 종료 승인 후 실행한다.
- 운영 저장이나 카카오톡 실제 전송은 검증 중 수행하지 않는다.
