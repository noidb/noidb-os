# BOX QR 코드 & 모바일 관리 데이터 설계

QR을 찍으면 해당 BOX 화면이 바로 열리도록, **이번 스프린트는 데이터 모델만** 설계한다.
QR 생성 로직, 스캔 화면, 실제 라우트(`/wms/box/[boxId]` 등)는 만들지 않는다 —
"기존 WMS 화면도 수정하지 않는다"는 이번 스프린트 규칙에 따라 새 화면도 아직 추가하지 않았다.

## 1. QR에 담을 값 (`WarehouseBox.qrValue`)

두 가지 방식을 검토했다.

| 방식 | 예 | 장점 | 단점 |
|---|---|---|---|
| **BOX ID만 인코딩** | `E-A-001` | 도메인이 바뀌어도(로컬↔배포 URL 등) QR을 다시 인쇄할 필요 없음 | 스캔 후 앱이 별도로 "이 값을 BOX ID로 해석해서 화면 이동"하는 로직 필요 |
| **전체 URL 인코딩** | `https://<도메인>/wms/box/E-A-001` | 스캔하면 바로 브라우저가 열림(별도 앱 로직 불필요) | 도메인이 바뀌면(현재 Cloudflare 임시 터널처럼) 모든 QR을 다시 인쇄해야 함 |

**추천: BOX ID만 인코딩하고, 스캔 후 처리는 앱이 담당한다.**
지금은 Cloudflare 임시 터널 주소를 쓰고 있어 도메인이 고정되어 있지 않다. 실제 배포 도메인이
확정되기 전까지는 QR에 절대 URL을 넣으면 도메인이 바뀔 때마다 전부 재인쇄해야 하므로,
**`qrValue`에는 BOX ID 문자열만 저장**하고, 스캔 이후 동작(경로 조합)은 실행 시점 설정값
(그때그때의 실제 배포 도메인)을 기준으로 앱이 만들도록 설계한다. `WarehouseBox.qrValue`는
현재 설계상 `id`와 같은 값이 될 예정이라 필드 자체가 중복처럼 보일 수 있지만, 향후 QR
인코딩 방식이 바뀔 가능성(예: 체크섬 포함, 버전 접두어 포함)에 대비해 `id`와 분리된 필드로
유지한다.

## 2. 스캔 후 라우팅 (설계만, 미구현)

향후 스프린트에서 아래와 같은 라우트를 추가하는 것을 제안한다 (지금은 만들지 않음):

```
/wms/box/[boxId]   →  해당 BOX의 "현재 BOX 보기" 화면으로 바로 이동
```

QR 스캔 자체는 표준 카메라 앱 또는 웹 카메라 API(`BarcodeDetector` 등)로 BOX ID 문자열을
읽어온 뒤, 클라이언트에서 `router.push(`/wms/box/${scannedBoxId}`)` 형태로 이동하는 흐름을
가정한다. 이 부분은 실제 구현 시점에 다시 설계를 구체화한다.

## 3. QR 인쇄 흐름 (설계만)

1. `BOX마스터` 시트(또는 화면)에서 BOX를 선택
2. `qrValue`(=BOX ID)로 QR 이미지를 생성 (클라이언트 라이브러리 사용 예정, 미확정)
3. 라벨 프린터 또는 일반 프린터로 출력해 실물 BOX에 부착

## 4. 모바일 관리 6개 기능 → 데이터 구조 매핑

"휴대폰 하나로 BOX를 관리한다"는 목표에 맞춰, 각 기능이 어떤 엔티티를 어떻게 다루는지
매핑한다 (화면은 만들지 않음, 데이터 흐름만 설계).

| 기능 | 대상 엔티티 | 동작 |
|---|---|---|
| **BOX 생성** | `WarehouseBox` | 새 행 추가. `id`는 카테고리+선반+순번 규칙으로 채번(자동 또는 수기), `status`는 기본값 `empty` |
| **BOX 수정** | `WarehouseBox` | `kind` / `series` / `isSetBox` / `maxModelCount` / `memo` / `status` / `sortOrder` 갱신 |
| **모델 이동** | `ModelLocation` | 대상 모델의 `primaryBoxId`(또는 `secondaryBoxId`)를 새 BOX ID로 갱신. 이동 후 이전 BOX와 새 BOX 양쪽의 "현재 모델 수"는 저장된 캐시가 아니라 그때그때 계산되므로 별도 동기화가 필요 없음(docs/WAREHOUSE_SHEET_DESIGN.md의 캐시 관련 권장사항 참고) |
| **현재 BOX 보기** | `WarehouseBox` + `ModelLocation` + `SkuLocation` | 읽기 전용 조회: 이 `boxId`를 가리키는 모델위치/SKU예외위치를 모아서 보여줌 (쓰기 없음) |
| **BOX 비우기** | `ModelLocation`, `SkuLocation`, `WarehouseBox` | 이 BOX를 가리키던 `ModelLocation.primaryBoxId`/`secondaryBoxId`를 비우고, 관련 `SkuLocation` 예외 행을 제거(또는 "무효" 표시)한 뒤 `WarehouseBox.status`를 `empty`로 변경 |
| **BOX 메모 수정** | `WarehouseBox` | `memo` 필드만 갱신 |

**공통 원칙**: 모바일 관리 기능은 전부 새 위치 시트(`BOX마스터`/`모델위치`/`SKU예외위치`)만
쓰고 읽는다. 기존 `제품DB`/`발주서 출력` 등 상품등록 기능 소유 시트는 어떤 모바일 관리
기능에서도 절대 쓰지 않는다(읽지도 않는다 — 조인은 상품명/이미지 등 표시용 정보를 보여줄
때만 읽기로 사용).

## 5. 아직 구현하지 않은 것 (다음 스프린트 후보)

- QR 생성/스캔 실제 코드
- `/wms/box/[boxId]` 라우트
- 모바일 관리 화면(BOX 생성/수정/이동/비우기 UI)
- 3개 위치 시트에 대한 실제 쓰기 기능 (이번 스프린트 규칙상 미구현)
