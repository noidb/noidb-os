# 거래처 발주 초안 일관성 수정 — 2026-09-08

## 사용자 요구
- 화면 어디서든 선택한 상품을 삭제하고 저장한다.
- 단종 처리완료 및 재고를 이용한 미납분 재발주요청 완료 SKU를 전송 전 초안에서 자동 제외한다.
- 메인과 주간업무가 같은 발주대기를 열고, 다른 창의 예전 초안이 저장된 수정·삭제를 덮어쓰지 않는다.
- 승인 뒤에도 상품 추가로 돌아가는 동선을 제공한다.
- 거래처 수정은 실제 목록을 펼쳐 선택할 수 있어야 한다.
- SKU 78490107 및 78490105 관련 모델의 거래처·이미지·색상·호수 누락을 정확 SKU 기준으로 보완한다.

## 확인된 원인
- 선택 삭제 UI는 상단에만 있었고 삭제 저장도 별도 단계였다.
- 완료 상태가 초안·출력 경로에서 조회되지 않았다.
- 승인·삭제 이력만 있어도 취합 대기열 ID를 교체했고 열린 창은 이전 ID를 계속 편집했다.
- 승인 상태에서는 editable 조건에 의해 상품 추가 버튼이 숨겨졌다.
- 거래처 입력의 datalist는 현재 입력값에 따라 후보가 제한되었다.
- 제품DB 최신 값이 있어도 초안의 빈 이미지·미등록 거래처·호수만 있는 옵션을 보완하지 않았다.

## 데이터 보호 원칙
- 직접 수정한 거래처·수량·메모·이미지는 보존한다.
- 단종대기나 다운로드만으로 완료 처리하지 않는다.
- 재발주 완료는 정확 SKU·원본 발주번호·시점·완료량을 대조한다. 일부 발주만 완료됐거나 원본 수량 근거가 부족하면 전체 삭제·임의 차감을 하지 않고 안내한다.
- 전송 및 입고·원가 이력은 유지한다. 발주에서 제외한 사실만 orderExclusion으로 보관한다.
- 실제 카카오톡 전송, 쿠팡 업로드, 운영 상품 삭제를 테스트로 수행하지 않는다.

## 사용 동선
- 메인과 주간업무 모두 /wms/vendor-orders/manage의 같은 활성 초안을 사용한다.
- 선택 시 화면 하단에 선택 삭제, 수정사항이 있으면 변경내용 저장 버튼이 표시된다.
- 승인 후에도 상품 추가·발주내용 수정 버튼으로 돌아갈 수 있다.
- 각 상품의 옵션 추가는 정확히 같은 모델의 다른 SKU를 표시한다. 이미 추가한 SKU와 단종 SKU는 선택되지 않는다.
- 다른 창의 최신 변경이 충돌하면 저장/출력/전송완료를 409로 차단한다. 기존 창의 입력은 남긴다.
- 단순 승인·삭제로 대기열을 바꾸지 않는다. 전송 이력이 생겨 새 대기열로 이동할 때도 현재 큐 수정값을 우선한다.
- SKU 78490107/78490105의 모델 wr011699은 13 SKU 확인: DB 이미지 등록 10개, 실제 미등록 3개. 이미 삭제된 SKU를 옵션 보충으로 재추가하지 않는다.
