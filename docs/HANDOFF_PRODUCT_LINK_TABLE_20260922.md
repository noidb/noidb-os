## 2. 사용자와 확정한 식별 규칙 (변경 없음)

**쿠팡 번호**
- 로켓 승인 후 옵션(모델SKU)마다 **SKU ID + 바코드 + 옵션ID**가 한 세트로 부여된다.
- **노출상품ID**는 링크(모델) 단위라서 옵션끼리 같은 게 정상이다.
- 예외: 한 SKU에 옵션ID가 2개일 수 있다(같은 노출상품ID). 예: 50277710 → 91058736384, 91058740631
- 옵션 1개만 노출상품ID가 갈라진 경우에는 **모델명이 같은 게 우선**이다(같은 제품). 이런 경우는 쿠팡에 **옵션결합 요청**해야 하는 업무다.

**내부 이름**
- 승인 전에는 **모델명**(사진 폴더 이름)과 **모델SKU**(모델명 + RG/SI/GO 등)만 있다.
- 상품명은 쿠팡이 바꾸므로 식별에 쓰지 않는다.
- 모델번호 규칙: 첫 글자는 성별(w 여성, m 남성), 둘째 글자는 종류(e 귀걸이, n 목걸이, r 반지, p 피어싱, s 세트 등).
- **번호는 앞자리 0까지 정확히 같아야 같은 제품이다** (we00130 ≠ we000130, mn000009 ≠ mn0009).
  - 예외는 사용자가 확인한 것만 인정한다(예: wa00268 폴더 = wa000268 제품).
- 세트(ws011406)의 사진은 구성품 폴더(wp011406)에 있는 경우가 많다.
- 중복 등록으로 한 제품에 SKU ID가 2~3개일 수 있다. 창고번호 "725(325)" 형태가 그 흔적이다.
- 폴더 중복을 피하려고 모델명을 바꿔 저장한 경우도 있다. 예: **we011623-1** = 모델SKU `we011623RG`, 진짜 사진은 `we011623 귀걸이` 폴더.

**제품코드**
- `P00001` 형식이며, 제품별로 가장 작은 SKU ID 순서로 부여했다. **한 번 부여하면 변경하거나 재사용하지 않는다.**
- **파일이나 폴더 이름은 절대 바꾸지 않는다.** 연결표(별칭 탭)에만 둔다.
- 묶는 순서: 모델명이 같으면 같은 제품 → 모델명이 비어 있으면 노출상품ID로 묶음 → 불확실하면 합치지 않고 검토필요로 둠.

**사진 검색 동작**
1. **이 모델 사진 검색**: 저장된 결과가 있으면 되살리고(1차 사진 + 고른 사진만), 없으면 **1차: 연결표 확정 폴더**만 연다.
   - 확정 폴더가 여러 모델을 담은 **묶음 폴더**이면 이 모델 하위 폴더만 연다(예: `2.큐빅H wb011625 we011623 …` 안의 `we011623 귀걸이`).
2. 사진이 부족할 때만 버튼으로 넓힌다. 새 사진은 뒤에 붙고 선택은 유지된다.
   - **2차**: 같은 폴더의 착용컷·공용 사진(모델번호 없는 사진·폴더)
   - **3차**: 같은 폴더의 다른 모델번호 폴더(정리 안 된 폴더는 여기에 섞여 있음, 30초 이상 걸릴 수 있음)
   - **4차**: 사진 폴더 전체 검색(예전 방식, 오래 걸림)
   - 묶음 폴더가 아니면 1차 다음이 바로 4차다. 연결표에 확정 폴더가 없는 모델(ms000129 등)은 처음부터 전체 검색한다.
3. **다시 검색 (1차부터)**: 1차부터 새로 읽는다(고른 사진은 뒤에 남김).
4. **검색 초기화**: 확인 창 후 그 모델의 저장 결과·선택·분석용·단계를 지운다. 사진 파일은 건드리지 않는다.
5. **전체 선택 (최대 10장) / 전체 해제**: 등록도우미가 10장까지만 받는다(대표 1 + 추가 9).
6. **분석용**: 모델당 1장. 분석용 없이 등록 준비를 누르면 멈추고 안내한다.
   - 등록도우미로는 분석용이 **맨 앞**으로 가서 AI 분석에 쓰이고, 선택한 사진 **전체(분석용 포함)**가 쿠팡 등록이미지 업로드 풀로 간다(사용자 결정).
7. **크게 보기**: 작은 사진을 누르면 열린다. ← → 넘기기, 마우스 휠 확대(최대 12배), 끌어서 이동, 더블클릭 3배, 다운로드(원본), 선택·분석용 지정.
8. 파일명과 크기가 완전히 같은 중복 사진은 1장만 보여준다. 목록은 60장씩 표시("60장 더 표시").
9. 등록도우미 → "사진 다시 고르기" 링크, 뒤로 가기 모두 보던 상태·검색어·사진이 유지된다.
10. 제품DB 자동 새로고침(창을 다시 누를 때, 20초 간격)은 목록을 지우지 않고 뒤에서 읽는다.

**속도 관련 사실**
- N 드라이브(`N:\개인\★전체제품사진`)는 **이동식 드라이브**로 잡힌다. 크롬에서 원본 읽기는 초당 2~3MB, PC에서 직접 읽어도 초당 5~10MB로 느리다.
- 그래서 목록용 작은 사진은 **JPEG 안에 들어 있는 미리보기**(파일 앞 128KB)를 쓰고, 없으면(보정 프로그램 내보내기본 등) 원본을 3장씩 200px로 줄인다.
- 만든 작은 사진은 크롬(IndexedDB `noidb-photo-thumbnails`)에 기억한다. we011623-1 2차 기준 처음 약 54초 → 두 번째 약 1초.
- 크게 보기·다운로드·등록 준비는 항상 **원본**을 쓴다(작은 사진 때문에 쿠팡 이미지가 깨지지 않는다).
- 더 빠르게 하려면 "개발 서버가 사진을 직접 읽고 줄인 사진을 E 드라이브에 저장"하는 방법이 있다. `sharp` **설치가 필요**하고 이 PC에서 켠 사이트에서만 된다. 사용자는 혼자 쓰므로 이 방식도 괜찮다고 했지만, 이번에는 "작은 사진 기억하기"로 충분해서 보류했다.

**운영 사이트에서 처음 쓸 때**
- 크롬 저장 공간은 사이트 주소마다 따로다. 운영 사이트에서는 **"사진 원본 폴더 연결"을 한 번 다시** 해야 하고, 검색 결과·작은 사진 기억도 새로 쌓인다.
- 운영 사이트 화면은 Claude가 직접 확인하지 못했다(Vercel 로그인 필요).

## 7. 주의사항 (사용자 지시)

- reset / clean / restore / checkout / stash / 삭제 / 덮어쓰기 금지. commit / push / merge / deploy는 승인 전 금지.
- 구글시트 쓰기, Apps Script 배포, 쿠팡 제출은 승인 전 금지. `.env.local` 비밀값 출력 금지(Claude의 `.env.local` 읽기는 보안 장치가 막는다).
- 사용자는 컴퓨터 작업이 어렵다. **한 번에 하나씩, 쉬운 순서로** 안내한다. 이미 받은 결과를 중복으로 검사하지 않는다.
- 보고에는 건수만 쓰고 원본 데이터를 통째로 붙이지 않는다. 보고 끝에 **[복사용 요약]** 블록을 붙인다.
- 개발 서버가 켜져 있을 때 `npm run build`를 하지 않는다(CLAUDE.md 참고). 배포 순서: 개발 서버 끄기 → `npm run build` → `main` push → Vercel 확인 → 개발 서버 다시 켜기.
- 사진 화면 확인이 필요할 때 Claude는 사용자 크롬(Claude in Chrome)에 자기 탭을 열어 확인할 수 있다. 확인 후 해당 모델을 검색 초기화로 원상복구하고 탭을 닫는다.
