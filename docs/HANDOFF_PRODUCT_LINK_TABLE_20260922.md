## 2. 사용자와 확정한 식별 규칙

**쿠팡 번호**
- 로켓 승인 후 옵션(모델SKU)마다 **SKU ID + 바코드 + 옵션ID**가 한 세트로 부여된다.
- **노출상품ID**는 링크(모델) 단위라서 옵션끼리 같은 게 정상이다.
- 예외: 한 SKU에 옵션ID가 2개일 수 있다(같은 노출상품ID). 예: 50277710 → 91058736384, 91058740631
- 옵션 1개만 노출상품ID가 갈라진 경우에는 **모델명이 같은 게 우선**이다(같은 제품). 이런 경우는 쿠팡에 **옵션결합 요청**해야 하는 업무다.

**내부 이름**
- 승인 전에는 **모델명**(사진 폴더 이름)과 **모델SKU**(모델명 + RG/SI/GO 등)만 있다.
- 상품명은 쿠팡이 바꾸므로 식별에 쓰지 않는다.
- 모델번호 규칙: 첫 글자는 성별(w 여성, m 남성), 둘째 글자는 종류(e 귀걸이, n 목걸이, r 반지, p 피어싱, s 세트 등).
- **번호는 앞자리 0까지 정확히 같아야 같은 제품이다** (we00130 ≠ we000130, mn000009 ≠ mn0009).
  - 예외는 사용자가 확인한 것만 인정한다(예: wa00268 폴더 = wa000268 제품).
- 세트(ws011406)의 사진은 구성품 폴더(wp011406)에 있는 경우가 많다.
- 중복 등록으로 한 제품에 SKU ID가 2~3개일 수 있다. 창고번호 "725(325)" 형태가 그 흔적이다.
- 폴더 중복을 피하려고 모델명을 바꿔 저장한 경우도 있다.

**제품코드 (신규 도입)**
- `P00001` 형식이며, 제품별로 가장 작은 SKU ID 순서로 부여했다. **한 번 부여하면 변경하거나 재사용하지 않는다.**
- **파일이나 폴더 이름은 절대 바꾸지 않는다.** 연결표(별칭 탭)에만 둔다. 과거에 번호 체계를 바꾸다 실패한 이유가 이것이다.
- 묶는 순서: 모델명이 같으면 같은 제품 → 모델명이 비어 있으면 노출상품ID로 묶음 → 불확실하면 합치지 않고 검토필요로 둠.
