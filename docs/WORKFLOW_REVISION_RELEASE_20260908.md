## 사용 순서

1. 사이트를 새로고침한다. 주간업무에서 처리 방법을 선택하고 `거래처 발주대기로 이동`을 누른다. 메인에서 직접 시작한다면 [거래처 발주대기](https://noidb-os.vercel.app/wms/vendor-orders/manage)의 `기존 발주대기 함께 취합`을 먼저 누른다.
2. 메인과 같은 거래처 발주대기에서 사진·거래처·발주수량을 수정한다. 사진 영역에서 Ctrl+V로 붙여넣는다.
3. 발주서를 승인하고 카카오톡 공유 또는 내려받은 이미지를 첨부한다. 실제 전송 후 전송완료를 표시한다.
4. 재발주요청·단종·쿠폰과 광고는 파일을 등록한 뒤 해당 실제 완료 버튼을 누른다. 완료한 상품과 파일은 진행 목록에서 사라진다.
5. 출고를 끝낸 작업은 메인 카드의 출고완료로 정리한다. 과거 기록에 Shipment 연결 정보가 부족한 작업도 이 버튼으로 완료할 수 있다.

- SKU 38256624는 실제 단종 상태 때문에 발주 선택이 막힌다. 단종·해제 관리 링크를 여는 것만으로 해제되지 않는다. 실제 상태 해제 처리 후 최신 자료로 다시 확인한다.
- 저장 중 통신이 끊겼다면 `발주대기 연결 다시 확인` 또는 `단종대기 완료 연결 다시 확인`을 이용한다. 저장 연결을 다시 확인하는 것이며 카카오톡 전송이나 쿠팡 신청을 반복하라는 뜻이 아니다.

## 추가로 보완한 저장 문제

- 취합 큐 내부의 수동 중복도 기존 대표 행을 유지하고 원본을 이력에 보관한다.
- 삭제된 초안·품목 ID를 새 발주에 재사용하지 않는다. 수량 0으로 보관한 행도 취합 과정에서 삭제하지 않는다.
- 초안 편집·저장 중에는 다시 취합해 미저장 내용을 잃지 않도록 막는다.
- 단종 완료는 생성한 정확한 SKU·요청 ID를 먼저 예약하고 큐 완료 저장을 다시 읽어 확인한 후 확정한다. 중간 실패는 같은 완료 버튼으로 재시도한다.
- 자동 출고완료와 수동 완료를 구분한다. 새 출력 세대에는 과거 자동 완료를 이어받지 않으며 같은 세대의 센터별 완료는 누적한다. 같은 Shipment 번호라도 실제 PO·SKU·바코드·수량 구성이 바뀌면 해당 Shipment만 다시 확인한다.
