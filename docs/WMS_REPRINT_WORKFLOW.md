# 바코드 일괄 재출력 기준

## 사용 순서

1. 작업센터에서 **재출력센터**를 연다.
2. 사진을 끌어다 놓거나 여러 사진을 선택한다. 바코드 전체·뒷자리·SKU·발주번호를 여러 줄로 검색해도 된다.
3. 결과는 기존 재출력 목록에 누적한다. 같은 SKU/바코드는 중복으로 담지 않으며 기존 장수를 유지한다.
4. 전체선택·전체해제 또는 개별 체크와 장수로 출력할 항목을 정한다.
5. **선택 바코드 한 파일로 저장**을 누른다. BarTender에서 XLSX 하나를 선택하여 출력한다.

전체해제는 목록 삭제가 아니다. 목록 비우기/개별 삭제 직후에는 **방금 지운 목록 복원**으로 되돌릴 수 있다. 다운로드 후에도 목록은 남는다.

## 보존 범위

- 목록·체크·장수·검색어는 현재 탭의 새로고침 및 화면 왕복에서 복원한다. 다른 PC나 별도 탭에 공용 저장한 운영 데이터는 아니다.
- 뒤로가기는 실제 브라우저의 직전 기록으로 이동하고, 저장한 스크롤 위치를 복원한다. 직전 WMS 기록이 없는 직접 진입은 작업센터로 간다.
- 공통 되돌리기는 복원 가능한 실제 작업이 있을 때만 표시한다. 재출력 목록 삭제 복원과 운영 작업 되돌리기를 혼동하지 않는다.
- 재출력은 발주 원본·피킹·재고·운송장·Shipment·제품DB를 변경하지 않는다.

## 사진과 검색 안전

- 사진은 브라우저의 로컬 판독기로 처리한다. 서버에는 판독한 검색 번호만 보낸다.
- 바코드 선 판독과 인쇄된 번호 OCR을 함께 사용한다. 큰 사진은 회전·구역별 인식 후 중복 제거한다.
- OCR은 높은 신뢰도의 완전한 번호만 사용한다. 누락된 숫자 추정, 문자/숫자 치환, 유사번호 자동 선택은 하지 않는다.
- 판독 번호는 발주서 원본과 **전체 바코드가 정확히 일치할 때만** 목록에 추가한다. 미매칭 번호는 별도 안내한다.
- 사진 인식은 기기·사진 크기·촬영 상태에 따라 시간이 걸리고 누락될 수 있다. 결과 개수를 표시하고 추가 사진을 누적할 수 있으며 분석 중단도 가능하다.
- 한 번에 사진 20장, 한 장 25MB 이하. 재출력 목록은 최대 200종이며 초과 시 일부만 추가하지 않는다.

## 고정된 출력 계약

`docs/WMS_SHIPMENT_OUTPUT_RULES.md`를 따른다. 숫자 순번, 전체 역순, `템플릿1` 시트, `BarTenderData` 표, 기존 8개 열과 완전한 옵션/반지 호수를 유지한다.

Shipment 출력세트와 바코드만 생성은 동일한 동봉내역서 정렬과 공통 BarTender 생성기를 사용한다. 상품명·바코드는 발주 원본에서, 최종 납품수량은 해당 Shipment 업로드 XLSX에서 검증한다. 제품DB에서는 모델 식별자와 제조국만 보강한다.

## 회귀 검사

- `npm run verify:reprint-selection`: 누적·중복·장수·전체해제·세션복원·상한·OCR 번호 추정 금지
- `npm run verify:wms-rules`: 출력 표·번호·역순·옵션·Manifest 정렬·PO/SKU 완전성·최종 수량
- `npm run verify:shipment-manifest-order`: 동봉내역서 정렬
- `node scripts/verify-reprint-browser.cjs`: 격리한 업무 API fixture에서 검색→선택→일괄 다운로드→새로고침→뒤로가기, 360/390/412/430/1920px
- `NOIDB_PHOTO_TEST_PATH`를 제공하면 실제 사진 파일 드롭과 실제 로컬 판독기를 검사한다. 참조 사진은 21종 정확한 번호 일치, 누락/가짜 번호 0을 요구한다. 사진 원본은 저장소에 넣지 않는다.

브라우저 fixture의 다운로드는 화면 동작 검사다. 실제 출력 데이터는 별도의 workbook 회귀 검사로 확인하며 물리 프린터 출력 성공을 대신 주장하지 않는다.
