# NOID-B OS 전체 사용자 매뉴얼

> 대상: NOID-B 상품등록 담당자, 발주·입고·피킹 담당자, 창고 관리자
> 사이트: <https://noidb-os.vercel.app/>
> 원칙: 화면에 표시되는 실제 기능을 기준으로 작성했으며, 외부 사이트의 최종 제출은 담당자가 직접 확인합니다.

## 1. 이 사이트는 무엇을 하는 곳인가요?

NOID-B OS는 업무를 두 영역으로 나눕니다.

| 상단 메뉴 | 하는 일 | 사용 대상 |
| --- | --- | --- |
| **AI 상품등록** | 새 상품 정보 정리, 이미지·상세페이지·라벨·견적서 생성, 쿠팡 등록 진행상태와 승인 SKU 관리 | 상품등록 담당자 |
| **작업센터** | 실제 발주서를 기준으로 거래처 발주, 입고, 피킹, Shipment 구성과 출력 | 발주·창고 담당자 |

중요: **WIMS, 상품공급상태, 반려 상품 처리는 모두 `AI 상품등록` 업무입니다.** 작업센터는 발주서와 창고 작업만 다룹니다.

---

## 2. 처음 사용할 때 알아둘 것

### PC와 모바일

- PC와 모바일에서 같은 주소를 사용합니다.
- PC에서는 폴더를 직접 선택하여 `상품이미지DB`에 저장할 수 있습니다.
- 모바일에서는 폴더 직접 저장을 지원하지 않으므로 ZIP을 내려받습니다. 실제 등록용 ZIP 생성이 성공하면 Google 제품DB도 함께 반영됩니다.
- 휴대폰 홈 화면에 추가하면 앱처럼 빠르게 열 수 있습니다.

### 관리자 확인이 나타나는 경우

제품DB나 운영 상태를 실제로 변경하는 버튼은 관리자 확인을 요구할 수 있습니다. 화면의 안내에 따라 잠금을 해제한 뒤 실행합니다. 조회·미리보기만 하는 기능은 먼저 안전하게 확인할 수 있습니다.

### 반드시 지켜야 할 안전 규칙

1. 연습·교육·화면 테스트는 반드시 **테스트·교육용**을 선택합니다.
2. **실제 등록용**은 실제로 Supplier Hub에 올릴 새 모델에만 사용합니다.
3. 기존 모델은 일괄 저장하지 않습니다. 필요한 파일만 개별 다운로드합니다.
4. 화면에 오류나 충돌이 나오면 임의로 강행하지 말고 해당 항목을 확인합니다.
5. 외부 사이트의 업로드·최종 제출 전에는 파일명, 상품명, 옵션, 수량을 사람이 마지막으로 확인합니다.

# A. AI 상품등록

## 3. 새 상품을 등록하는 전체 순서

가장 일반적인 순서는 아래와 같습니다.

1. 제품사진 등록
2. AI 분석
3. 기본정보 확인·수정
4. 쿠팡·Google·1688에서 동일 상품 조사
5. 쿠팡 등록 이미지 배치
6. 상세페이지 생성
7. 테스트 또는 실제 등록파일 생성
8. Supplier Hub에 파일과 견적서 업로드
9. WIMS에서 등록 결과 수집
10. 승인 후 상품공급상태를 수집하여 기존 제품DB 행에 SKU·바코드·상태 연결

## 4. 1단계 — 제품사진

### 하는 일

AI가 상품의 카테고리, 소재, 색상, 형태, 위험 요소 등을 판단할 참고 사진을 넣습니다.

### 사용법

1. `제품사진` 영역에 상품 사진을 올립니다.
2. 사진은 최대 10장까지 넣을 수 있습니다.
3. 잘못 올린 사진은 `삭제`, 자세히 볼 사진은 `확대`를 누릅니다.
4. `AI로 제품 분석`을 누릅니다.

주의: 여기의 사진은 **분석용**입니다. 쿠팡에 실제 업로드할 이미지는 5단계의 `쿠팡 등록 이미지` 칸에 따로 넣습니다.

## 5. 2단계 — AI 분석 결과

AI가 추정한 상품 특징, 각인 여부, 위조상품 위험, 판단 이유와 신뢰도를 보여줍니다.

- 결과는 참고자료입니다.
- 실제 상품과 다르면 다음 단계의 입력값을 직접 고칩니다.
- 상표, 캐릭터, 디자인권 문제가 의심되면 등록 전에 반드시 다시 확인합니다.

## 6. 3단계 — 기본정보 확인

상품 등록과 파일 생성에 사용할 핵심 정보를 확인합니다.

주요 항목은 거래처, 카테고리, 성별, 소재, 색상, 사이즈, 치수, 모델번호, 모델명, 창고번호, 쿠팡 상품명, 검색태그, 공급가, 판매가, 등록상태 등입니다.

### 입력 원칙

- **모델명**은 상품을 구분하는 핵심값입니다. 실제 저장 전에 중복 여부를 확인합니다.
- 옵션이 여러 개면 색상·사이즈·옵션명을 실제 상품과 정확히 맞춥니다.
- 쿠팡 상품명과 검색태그는 자동값을 사용할 수 있고, 필요할 때만 직접 수정합니다.
- 재등록 상품은 기존 등록행 연결 기능을 사용할 수 있지만, 연결 대상과 이관 결과를 확인한 뒤 기존행 삭제 여부를 결정합니다.

## 7. 4단계 — 쿠팡·Google·1688 검색

### 버튼별 용도

- `쿠팡 검색`: 동일·유사 상품 판매 여부와 가격 확인
- `Google 이미지 검색`: 동일 제품 이미지와 출처 확인
- `1688 이미지 검색`: 중국 공급처 후보 확인
- `사진으로 1688 검색어 정밀 분석`: 사진을 바탕으로 중국어·영어 검색어 생성

생성된 검색어는 `복사`하여 검색창에 붙여넣습니다. 찾은 공급처 주소는 링크 칸에 넣고 `링크 저장`을 누르면 다시 열거나 복사할 수 있습니다.

PC에서는 `상품DB 폴더 선택` 후 모델 폴더를 만들고, 찾은 이미지를 저장할 수 있습니다.

## 8. 5단계 — 쿠팡 등록 이미지

### 하는 일

Supplier Hub에 올릴 실제 이미지를 용도별로 배치합니다.

### 사용법

1. 여러 이미지를 한 번에 업로드합니다.
2. 메인 착용컷, 전체옵션 이미지, 색상별 썸네일, 디테일컷, 착용컷 칸에 맞게 배치합니다.
3. 필요한 칸은 `+ 전체옵션 이미지`, `+ 디테일컷`, `+ 착용컷`으로 추가합니다.
4. 순서가 잘못되면 재배치하고, 필요 없는 이미지는 삭제합니다.
5. 흰 배경 여백이 필요하면 `흰 배경 캔버스 맞춤`에서 미리보기 후 확정합니다.

`쿠팡 이미지 전체 초기화`는 현재 배치를 비우므로, 실제 작업 중에는 누르기 전에 다시 확인합니다.

## 9. 6단계 — 상세페이지

### 새로 만드는 경우

1. 상세페이지에 넣을 이미지를 원하는 순서로 배치합니다.
2. NOID-B 기본 상단 로고를 사용하거나 별도 상단 이미지를 넣습니다.
3. 필요하면 하단 이미지를 추가합니다.
4. `상세페이지 만들기`를 누릅니다.
5. 결과 이미지를 확대하여 순서, 잘림, 잘못된 사진이 없는지 확인합니다.

### 이미 완성된 상세페이지가 있는 경우

완성된 긴 이미지를 올려 그대로 사용할 수 있습니다. 다시 생성할 필요가 없으면 개별 `상세페이지만 다운로드`를 이용합니다.

주의: 상세페이지에 엉뚱한 사진을 넣고 실제 일괄 저장을 다시 누르더라도 기존 모델의 덮어쓰기는 차단됩니다. 그래도 실제 저장 전 미리보기를 확인하는 것이 가장 안전합니다.

## 10. 이미지 자동생성 화면

상단의 `이미지 자동생성`을 누르면 상품 이미지 제작 전용 화면으로 이동합니다.

진행 순서:

1. 상품 기본정보 입력
2. 참고사진 등록 및 사진 역할 지정
3. 분석 결과와 기준 이미지 승인
4. 색상별 썸네일 생성
5. NOID-B 모델 템플릿과 착용컷 생성
6. 전체 색상 옵션컷 조합
7. 디테일 확대컷 구성
8. 순서 확인 후 Google Drive 또는 이 PC 폴더에 저장

생성 결과가 마음에 들지 않으면 저장 전에 다시 만들고, 최종 승인된 이미지만 상품등록 화면에 사용합니다. AI 이미지 생성은 비용이 발생할 수 있으므로 같은 요청을 불필요하게 반복하지 않습니다.

## 11. 7단계 — 임시저장과 개별 파일 다운로드

### 임시저장

- `임시저장`: 작성 중인 상품을 저장합니다.
- `임시저장 불러오기`: 저장된 상품을 이어서 작업합니다.
- 최대 20개까지 표시됩니다.
- 불필요한 초안은 목록에서 삭제합니다.

### 개별 다운로드

일괄 저장 없이 필요한 것만 만들 수 있습니다.

- `견적서만 다운로드`
- `상세페이지만 다운로드`
- `썸네일 + 추가이미지만 다운로드`
- `라벨만 저장` 또는 `라벨만 다운로드`

### 라벨만 만드는 방법

1. 모델명, 제조연월, 제조자, 수입자명을 확인합니다.
2. 현재 상품정보가 기본값으로 들어오므로 수정할 내용만 고칩니다.
3. `라벨만 저장`을 누릅니다.
4. PC에서 상품DB 폴더가 연결되어 있으면 `상품이미지DB\라벨`에 JPG로 저장됩니다. 연결되지 않은 환경은 JPG를 다운로드합니다.

## 12. 테스트·교육용과 실제 등록용의 차이

### 테스트·교육용

- 버튼: `테스트 ZIP 생성`
- 결과: 연습용 ZIP만 다운로드
- 실제 상품 폴더 변경 없음
- Google 제품DB 변경 없음
- 아무 값이나 넣어 기능을 연습할 때 사용

### 실제 등록용

- 버튼: `실제 등록파일 일괄 생성 및 저장`
- 새 모델만 1회 저장
- 기존 모델·기존 파일 덮어쓰기 차단
- PC: 선택한 상품이미지DB 폴더에 저장하고 Google 제품DB 반영
- 모바일: ZIP을 다운로드하고 성공 후 Google 제품DB 반영
- 실행 후 자동으로 다시 연습 모드로 돌아감

실제 등록 버튼을 누르면 확인창이 나옵니다. 상품명, 모델명, 이미지가 모두 실제 등록 대상일 때만 승인합니다.

## 13. 실제 등록파일 저장 후 해야 할 일

성공하면 `실제 등록파일 준비 완료`가 표시됩니다.

1. `저장 폴더 열기`로 생성 파일을 확인합니다.
2. `Supplier Hub 대량상품등록 열기`를 누릅니다.
3. Supplier Hub에서 상품 이미지, 상세페이지, 견적서 등 필요한 파일을 업로드합니다.
4. 쿠팡 화면에서 최종 검토 후 직접 제출합니다.

NOID-B OS는 파일 준비와 제품DB 반영을 도와주지만, Supplier Hub의 최종 제출 버튼까지 대신 누르지는 않습니다.

## 14. 카테고리별 묶음 견적서

실제 등록한 상품은 성별·카테고리별 견적서 대기목록에 누적됩니다.

- 같은 성별·카테고리를 최대 1,000 SKU행 단위로 나눕니다.
- `묶음 견적서 다운로드`로 최신 Google 제품DB 기준 견적서를 만듭니다.
- 업로드까지 끝난 뒤에만 `목록 비우기`를 누릅니다.
- 잘못 들어간 모델은 해당 모델의 `×`로 개별 제거할 수 있습니다.

## 15. 8단계 — WIMS 등록 진행상황

WIMS는 상품 등록이 접수됐는지, 검수완료인지, 반려인지 확인하는 곳입니다.

### 최초 1회: 브라우저 확장기능 설치

1. AI 상품등록 화면의 `최초 1회 확장 기능 받기`를 누릅니다.
2. 받은 ZIP의 압축을 풉니다.
3. Chrome은 `chrome://extensions`, Edge는 `edge://extensions`를 엽니다.
4. `개발자 모드`를 켭니다.
5. `압축해제된 확장 프로그램을 로드합니다`를 누르고 압축을 푼 폴더를 선택합니다.
6. 확장기능을 새 버전으로 교체했다면 확장기능 화면에서 `새로고침`을 누릅니다.

### 매번 수집하는 방법

1. Supplier Hub의 `상품 등록 상태 확인(WIMS)` 화면을 엽니다.
2. 조회 기간과 조건을 정하고 검색합니다.
3. 확장기능의 `WIMS 전체를 NOID-B로 전송`을 누릅니다.
4. NOID-B OS로 돌아와 수집 건수와 분류 결과를 확인합니다.

직접 드래그해 복사·붙여넣기는 비상용입니다. 평소에는 확장기능을 사용합니다.

### 상태 처리

- `검수완료`: 승인 SKU 연결 후보로 사용
- `반려`: 반드시 `등록불가` 또는 `재등록시도` 중 하나를 선택
- `검수중`: 기다렸다가 다음 수집 때 다시 확인
- 범위에서 찾지 못한 상품: 다른 조회 기간이나 다른 WIMS 페이지에 있는지 확인

반려사유를 NOID-B OS에서 별도로 확인할 수 없는 경우가 있으므로, 운영 결정은 두 가지로 단순화합니다.

- `등록불가`: 더 이상 등록하지 않을 상품
- `재등록시도`: 내용을 고쳐 다시 등록할 상품

## 16. 상품공급상태 수집과 제품DB 갱신

상품이 승인되면 Supplier Hub의 상품공급상태 관리에서 SKU, 바코드, 상품명, 발주가능상태를 가져옵니다.

### 수집 방법

1. Supplier Hub의 상품공급상태 관리 화면을 엽니다.
2. 필요한 검색 조건으로 전체 목록을 조회합니다.
3. 브라우저 확장기능에서 상품공급상태 전체 전송 버튼을 누릅니다.
4. AI 상품등록 화면의 `상품공급상태 안전 진단`에서 최신 자료를 진단합니다.
5. 충돌·중복·미매칭을 먼저 확인합니다.
6. 안전한 항목만 관리자 확인 후 제품DB에 반영합니다.

### 자동 반영 원칙

- `R`로 시작하는 바코드만 로켓상품 관리 대상입니다.
- `S`로 시작하는 바코드는 제외합니다.
- 제품DB에 새 행을 만들지 않습니다.
- 신규 승인 상품은 이미 만들어 둔 `신상품승인대기` 행에 SKU·바코드·발주가능상태를 채웁니다.
- 기존 SKU는 SKU로 찾아 변경 가능한 상품명과 발주가능상태만 갱신합니다.
- 바코드는 SKU별 불변값으로 취급합니다.
- 바코드 충돌, 중복 후보, 미매칭은 자동으로 억지 연결하지 않습니다.
- 실제 반영 전 백업 파일이 만들어지며, 화면의 진단 결과를 먼저 확인합니다.

## 17. 기타 쿠팡 데이터 수동 업데이트

접힌 `기타 쿠팡 데이터 수동 업데이트` 영역은 필요한 경우에만 사용합니다.

- 입고상세 자료: 실제 입고와 누적입고 관련 값 갱신
- PO/SKU 자료: 발주 관련 SKU 정보 갱신
- 쿠팡 추출DB: 기존 행의 상품링크, 쿠팡 노출가, 재고현황 갱신

이 기능들도 기존 제품DB 행을 기준으로 하며, 화면에 `신규행 0`이라고 표시되는 작업은 새 상품 행을 만들지 않습니다.

# B. 작업센터 — 발주서 업무

## 18. 작업센터 전체 순서

작업센터는 아래 순서로 사용합니다.

1. 신규 발주서 업데이트
2. 부족분 거래처 발주
3. 거래처 입고 처리와 통합 피킹
4. 피킹 결과 확정과 발주확인 파일 생성
5. Shipment 구성
6. 송장·Shipment·출력세트 생성

## 19. 신규 발주서 업데이트

1. `작업센터`로 이동합니다.
2. `신규발주서 업데이트`를 누릅니다.
3. 최신 발주서 목록과 반영 결과를 확인합니다.
4. 입고예정일, 발주번호, 물류센터, 상품과 수량을 확인합니다.
5. 진행 중인 피킹 웨이브가 있으면 중복으로 새 웨이브를 만들지 않습니다.

PC 자동수집기를 사용하는 경우, Supplier Hub에서 발주리스트를 다운로드하면 다운로드 폴더 감지 이후의 중복검사·업로드·반영을 자동화할 수 있습니다. 로그인과 Supplier Hub 다운로드 자체는 사용자가 직접 합니다.

## 20. 거래처 발주관리

부족 재고를 거래처별 발주서로 묶어 관리합니다.

### 피킹 중 부족분에서 만드는 방법

1. 피킹 화면에서 부족 수량을 입력합니다.
2. 부족 상품을 거래처 발주 대상으로 추가합니다.
3. `거래처 발주관리`에서 거래처별 수량과 메모를 확인합니다.
4. 거래처 미지정 상품은 실제 거래처를 지정합니다.
5. 필요하면 상품검색으로 저재고 상품을 추가합니다.
6. 저장 후 거래처 발주서를 내려받아 거래처에 전달합니다.

### 피킹과 무관한 수동 발주

`거래처 발주관리`의 수동 발주 화면에서 상품을 검색해 임시 발주서를 만들 수 있습니다. 이미 발주한 상품을 중복 추가하지 않도록 모델명·SKU·수량을 확인합니다.

## 21. 거래처 발주서 입고

1. `발주서 입고관리`를 엽니다.
2. 입고할 거래처 발주서를 선택합니다.
3. 담당자와 실제 입고 수량을 확인합니다.
4. 전부 들어왔으면 전체 입고, 일부만 왔으면 상품별 입고 수량을 입력합니다.
5. 늦게 오는 상품은 `입고지연`, 해소되면 `지연해제`를 사용합니다.
6. 단종 상품은 `단종처리`, 다시 판매 가능하면 `단종해제`를 사용합니다.
7. 필요하면 현재고 0 처리, 재발주 목록 추가, 잘못된 줄 삭제를 사용합니다.
8. 마지막으로 `저장`합니다.

전체 입고를 잘못 처리했다면 화면에서 제공하는 마지막 전체 입고 취소 기능으로 즉시 되돌립니다. 삭제·단종·현재고 변경은 실제 운영정보를 바꾸므로 선택 대상을 꼭 확인합니다.

## 22. 통합 피킹 웨이브 만들기

1. 작업센터에서 `통합 피킹 시작 (실제 발주 기준)`을 누릅니다.
2. 입고예정일별 실제 발주서를 확인합니다.
3. 함께 피킹할 발주서를 선택합니다.
4. 웨이브 이름과 작업자를 입력합니다.
5. 미리보기에서 물류센터, 발주번호, SKU, 총수량을 확인합니다.
6. 피킹 웨이브를 생성합니다.

한 발주서는 피킹과 Shipment의 최소 단위입니다. 같은 발주서를 둘로 나누거나 동시에 두 웨이브·두 Shipment에 넣지 않습니다.

## 23. 피킹 진행

피킹 화면은 같은 SKU의 여러 발주 수량을 묶어 보여 주되, 원래 발주번호와 바구니 연결을 보존합니다.

1. 상품 이미지, 상품명, 옵션, SKU, 창고 위치를 확인합니다.
2. 지정된 바구니와 발주번호를 확인합니다.
3. 전량 찾았으면 전량 완료로 처리합니다.
4. 일부만 찾았으면 실제 찾은 수량을 입력합니다.
5. 못 찾았으면 미발견으로 처리합니다.
6. 재고 부족분은 거래처 발주서에 추가합니다.
7. 필요하면 상품 상세에서 현재고, 단종·과재고 등 운영정보를 수정합니다.
8. 모든 상품을 처리한 뒤 결과 확인 화면으로 이동합니다.

상품 이미지 삭제나 운영상태 변경은 선택된 SKU에 영향을 주므로 여러 상품을 선택했을 때 특히 주의합니다.

## 24. 피킹 완료 후

1. 피킹 결과에서 찾은 수량과 부족 수량을 최종 확인합니다.
2. 잘못된 결과는 확정 전에 수정합니다.
3. 부족분 거래처 발주서를 확인합니다.
4. 선택한 발주서의 발주확인 파일을 한 번에 생성합니다.
5. 파일을 쿠팡 또는 필요한 외부 화면에 직접 업로드합니다.
6. 완료된 발주 묶음으로 Shipment를 구성합니다.

# C. Shipment와 출력

## 25. Shipment 만들기

1. 작업센터의 `쉽먼트` 또는 `/wms/shipment`로 이동합니다.
2. 완료된 피킹 웨이브의 발주서 후보를 확인합니다.
3. 함께 보낼 발주서를 선택합니다.
4. 분할 미리보기로 Shipment 묶음을 확인합니다.
5. Shipment를 생성합니다.
6. 필요하면 이름을 수정합니다.

### 고정 원칙

- 완료된 피킹 결과만 후보가 됩니다.
- 발주서 한 건 전체가 하나의 단위입니다.
- 한 발주서를 SKU별로 쪼개지 않습니다.
- 같은 발주서를 두 Shipment에 중복 포함하지 않습니다.
- 물류센터와 입고예정일이 다른 발주서는 별도 그룹으로 유지합니다.
- Shipment 삭제는 Shipment 기록만 삭제하며 원래 피킹 결과를 바꾸지 않습니다.

## 26. Shipment 상세 3단계

### 1단계: 송장출력용 파일 생성

현재 Shipment에 포함된 발주서를 기준으로 한진 송장출력용 파일을 만듭니다. 미리보기의 발주 수와 배송그룹 수를 확인한 뒤 생성합니다.

### 2단계: Shipment 파일 생성

최신 송장 결과와 확정수량 자료를 찾아 같은 발주 묶음의 Shipment 업로드 파일을 생성합니다. 발주번호·송장번호·센터가 완전히 맞지 않으면 생성하지 않습니다.

### 3단계: Shipment 출력세트 생성

`Shipment 출력세트 생성`을 누르면 ZIP 하나에 아래 3개 파일이 들어갑니다.

1. `01_부착문서_4분할.pdf`
2. `02_동봉내역서_통합.pdf`
3. `바코드출력_날짜_최종.xlsx`

필요한 경우 `바코드 파일만 생성` 또는 `물류센터 라벨만 생성`도 사용할 수 있습니다.

### 출력 순서 원칙

- 바코드 XLSX의 `쉽먼트구분`과 상품 행 순서는 동봉내역서의 상품 순서를 기준으로 맞춥니다.
- 실제 인쇄 후 쌓이는 순서를 고려하여 전체 상품·구분 행이 역순으로 구성됩니다.
- 바코드 파일을 임의로 재정렬하지 않습니다.
- 상품명과 옵션은 발주서 원문을 기준으로 하며, 첫 쉼표 앞은 상품명, 뒤는 옵션으로 사용합니다.
- 바코드 모델명은 영문·숫자로 확인 가능한 모델 식별자만 사용합니다. 확인할 수 없으면 임의 생성하지 않습니다.

출력세트는 발주번호 집합이 완전히 일치할 때만 생성됩니다. 누락, 예상 외 발주, 중복, 바코드 충돌 메시지가 나오면 원본 파일과 현재 Shipment를 다시 확인합니다.

# D. 창고관리

## 27. 창고관리의 현재 범위

창고관리 화면은 실제 창고 위치를 정리하기 위한 기능입니다. 현재 화면 안내 기준으로 **브라우저 로컬 임시 저장**이며 Google 시트에는 쓰지 않습니다. 다른 PC나 브라우저로 자동 공유되는 영구 데이터라고 생각하면 안 됩니다.

## 28. 구역·선반 관리

1. `구역·선반 관리`를 엽니다.
2. Zone ID, 이름, 카테고리, 정렬순서, 사용상태를 입력해 구역을 만듭니다.
3. 구역을 선택하고 선반코드, 선반명, 정렬순서, 사용상태를 입력합니다.
4. 기존 항목은 `수정`으로 변경합니다.

예: Zone `E`, 선반코드 `A`이면 선반 ID는 `E-A` 형식입니다.

## 29. BOX 등록과 관리

### BOX 등록

1. 구역과 선반을 선택합니다.
2. BOX 종류, 카테고리, 시리즈, 세트상품 전용 여부를 입력합니다.
3. 필요하면 최대 모델 수와 메모를 입력합니다.
4. 자동 추천된 BOX ID를 확인합니다. 예: `E-A-001`
5. `저장`을 누릅니다.
6. 연속 등록은 `다음 BOX 연속 등록`을 사용합니다.

### BOX 상세

- QR 미리보기
- BOX 속성 수정
- 들어있는 모델 확인과 이동
- SKU 예외 위치 확인
- 해당 BOX에 모델 추가
- BOX 비우기

`BOX 비우기`는 연결된 위치정보에 영향을 주므로 실제로 빈 박스인지 확인한 뒤 사용합니다.

## 30. 모델 위치와 SKU 예외 위치

### 모델 위치

1. 모델명·SKU·상품명으로 검색합니다.
2. 모델을 선택합니다.
3. 기본 BOX를 지정합니다.
4. 여러 BOX에 나뉜 경우에만 보조 BOX를 지정합니다.
5. 전체 옵션이 같은 BOX인지, 세트상품인지 명시합니다.
6. 필요하면 메모를 적고 저장합니다.

### SKU 예외 위치

같은 모델의 대부분 옵션은 기본 BOX에 있지만 특정 SKU만 다른 곳에 있을 때 사용합니다.

1. SKU를 선택합니다.
2. 예외 BOX ID를 선택합니다.
3. 예외 사유와 메모를 입력합니다.
4. 저장합니다.

## 31. 기존 창고번호 이전과 위치 검증

### 기존 창고번호 이전

기존 `legacyLocation`을 새 BOX ID로 옮길 때 사용합니다.

1. 기존 위치를 검토 상태로 바꿉니다.
2. 실제 새 BOX ID를 확인합니다.
3. 맞으면 확정하고, 지금 처리하지 않을 항목은 건너뜁니다.

### 위치 검증

미배치 모델, 중복 위치, 존재하지 않는 BOX 연결 등 문제를 검사합니다. 문제 항목을 누르면 수정 화면으로 이동할 수 있습니다. 창고 위치를 대량 수정한 뒤에는 반드시 다시 검증합니다.

# E. 자주 하는 업무별 빠른 안내

## 32. 라벨만 급하게 만들기

`AI 상품등록` → 기본정보에서 모델명 확인 → 7단계에서 제조연월·제조자·수입자 확인 → `라벨만 저장/다운로드`

## 33. 교육용으로 전체 흐름 연습하기

아무 상품정보 입력 → 이미지 배치 → 상세페이지 확인 → `테스트·교육용` 선택 → `테스트 ZIP 생성`

이 경우 실제 상품 폴더와 Google 제품DB는 변경되지 않습니다.

## 34. 반려 상품 처리하기

Supplier Hub WIMS 검색 → 확장기능으로 전체 전송 → AI 상품등록 8단계에서 반려 상품 확인 → `등록불가` 또는 `재등록시도` 선택

## 35. 승인된 새 SKU 연결하기

Supplier Hub 상품공급상태 검색 → 확장기능으로 전체 전송 → 안전 진단 → 신규 승인 후보와 충돌 확인 → 안전 항목만 관리자 확인 후 반영

## 36. 새 발주부터 출력까지

작업센터 → 신규발주 업데이트 → 거래처 부족분 발주 → 입고관리 → 통합 피킹 → 결과 확정 → 발주확인 파일 → Shipment 구성 → 송장출력용 파일 → Shipment 파일 → 출력세트

# F. 오류가 났을 때

## 37. 상품DB 폴더가 열리지 않음

- PC 브라우저에서 다시 `상품DB 폴더 선택`을 누릅니다.
- 이동식·네트워크 드라이브가 연결되어 있는지 확인합니다.
- 모바일은 폴더 열기 대신 ZIP 다운로드를 사용합니다.

## 38. 기존 모델이라 실제 저장이 차단됨

정상 안전장치입니다. 기존 모델을 덮어쓰지 말고 `상세페이지만`, `라벨만`, `견적서만`, `썸네일 + 추가이미지만` 중 필요한 개별 다운로드를 사용합니다.

## 39. WIMS 또는 상품공급상태가 들어오지 않음

1. 확장기능이 켜져 있는지 확인합니다.
2. 새 버전을 받은 뒤 확장기능 화면에서 새로고침했는지 확인합니다.
3. Supplier Hub 검색 결과가 화면에 표시된 상태인지 확인합니다.
4. 다시 전체 전송합니다.
5. 그래도 안 되면 비상용 붙여넣기를 사용합니다.

## 40. 제품DB 미매칭 또는 바코드 충돌

- 자동 반영하지 않습니다.
- 모델SKU, 옵션, 상품명, 기존 SKU를 비교합니다.
- 같은 바코드가 다른 SKU에 연결되어 있으면 어느 쪽이 실제 상품인지 확인합니다.
- 확인 전에는 제품DB 행을 새로 만들거나 바코드를 바꾸지 않습니다.

## 41. Shipment 출력세트 생성 실패

- 현재 Shipment의 발주번호와 원본 파일의 발주번호가 완전히 같은지 확인합니다.
- 입고예정일 폴더에 부착문서·동봉내역서·바코드 원본이 모두 있는지 확인합니다.
- 송장번호, 물류센터, 발주번호 누락 여부를 확인합니다.
- 다른 날짜나 다른 Shipment의 파일을 섞지 않습니다.

## 42. 화면에는 있지만 아직 운영용이 아닌 메뉴

`입고관리(/wms/inbound)`와 `재고관리(/wms/inventory)` 독립 화면은 현재 개발용 골격입니다. 실제 입고는 `발주서 입고관리`, 실제 재고 관련 작업은 피킹·거래처 입고·상품 운영정보 화면을 사용합니다.

# G. 관리자용 운영 체크리스트

## 매일 또는 작업 시작 전

- [ ] 사이트가 정상 열리는지 확인
- [ ] PC의 상품이미지DB·쿠팡데이터 드라이브가 연결됐는지 확인
- [ ] 브라우저 확장기능이 최신이고 켜져 있는지 확인
- [ ] 신규 발주서 업데이트 확인
- [ ] 진행 중인 피킹 웨이브와 부족분 발주서 확인

## 실제 상품등록 전

- [ ] 새 모델명이 맞고 중복이 아닌지 확인
- [ ] 상품명·옵션·가격·공급가 확인
- [ ] 썸네일과 상세페이지에 다른 상품 사진이 없는지 확인
- [ ] 라벨의 모델명·제조연월·제조자·수입자 확인
- [ ] `실제 등록용` 선택 여부 확인

## 제품DB 반영 전

- [ ] WIMS와 상품공급상태 자료의 수집 시각 확인
- [ ] R바코드 대상인지 확인
- [ ] 신규행 생성 0건인지 확인
- [ ] 바코드 충돌·중복·미매칭 확인
- [ ] 안전 항목만 선택했는지 확인

## Shipment 출력 전

- [ ] 피킹 결과가 확정됐는지 확인
- [ ] 발주서가 중복 Shipment에 포함되지 않았는지 확인
- [ ] 물류센터와 입고예정일이 같은 묶음인지 확인
- [ ] 출력세트 3개 파일이 모두 생성됐는지 확인
- [ ] 바코드 XLSX를 임의 정렬하지 않았는지 확인
