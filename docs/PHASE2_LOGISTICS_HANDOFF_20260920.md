# 2단계 로컬 구현과 검증 기록 — 2026-09-20

사용자가 Aside의 9월 17일 처리 기록을 초기 기준으로 승인했다. `codex/current-logistics-flow`, `E:\노이드비AI`에서 수정했다. 기존 미커밋 변경은 보존했고 이번 단계는 사용자 화면 검토 전이므로 커밋·push·배포하지 않았다.

## 구현

- Aside 파일에서 확인한 마감 25건은 재분류 대상에서 제외한다. 당시 미마감 18건과 1단계 출고완료 기록의 쉽먼트가 수집 대상이다. 입고예정일이 오래됐다는 이유로 제외하지 않는다.
- 초기 자료는 `lib/wms/logistics-aside-baseline.json`에 원본 경로와 함께 보관한다. 마케팅 처리완료 SKU 801개, 제외 SKU 34개, 연결 가능한 선처리 행 38건을 포함한다. 복수 발주서의 수량이나 불명확한 공급상태는 추정하지 않는다.
- 확장 0.9.4는 대상 번호를 한 번에 받아 로그인된 쿠팡의 쉽먼트 상세를 읽는다. 모든 대상의 수집과 검증이 성공한 경우에만 v2 전체 조회 결과를 저장한다. 취소·상세 오류·로그인 전환·불일치에는 일부 결과를 성공으로 저장하지 않는다.
- 계산은 마감된 쉽먼트의 실제 납품수량에서 입고수량을 뺀다. 식별은 쉽먼트·박스·발주번호·SKU다. 사진 등으로 선처리한 수량은 해당 출처에서만 차감한다. 미마감은 대기, 마감 입고 0이나 증빙 변경은 검토 대상으로 둔다.
- 새 화면은 마감대기 / 입고결과 / 후속처리 / 처리이력으로 나뉜다. 최초 진입 한 번과 사용자의 새로고침, 분류 성공 직후 한 번만 저장 자료를 읽는다. 쿠팡을 자동으로 조회하거나 다음 화면으로 이동하지 않는다.
- 미납 분류는 기존 거래처·재발주·단종 작업으로, 사용자가 검토한 초도 후보는 기존 쿠폰·광고 작업으로 연결한다. 원래 출처와 수량을 남겨 재시도 중복을 막는다. 대기열 이동과 쿠팡 업로드 등 실제 업무완료는 구분한다.
- 재발주 큐와 거래처 초안에는 새 쉽먼트 출처별 수량을 유지하는 보완만 적용했다. 같은 발주/SKU의 다른 쉽먼트를 누락하거나 완료수량을 각 출처에 중복 기록하지 않는다. 기존 자료와 충돌하면 자동 합산하지 않는다.

## 로컬 확인

미리보기: `http://localhost:3111/wms/inbound/shipments?logisticsFixture=1`

개발 환경 전용 가상 8개 쉽먼트·20개 발주를 실제 계산 함수에 넣었다. 실제 업무 자료를 저장하거나 쿠팡에 전송하지 않는다.

통과한 검사:

- `scripts/verify-logistics-receipts.ts`: 초기 기준, 전체 조회 검증, 마감 계산, 수량 변경, 중복 방지.
- `scripts/verify-logistics-receipt-extension.cjs`: 상세 표 수집, 기존 미마감 18건, 빈/부분 발주 목록, 발주 불일치·오류 차단.
- `scripts/verify-logistics-reorder-material.cjs`: 출처별 합산·완료, 기존 자료 충돌, 중복 출처와 잘못된 수량 차단.
- `scripts/verify-logistics-receipt-routing.ts`: 분류 재시도, 오래된 결과 차단, 선처리 수량, 마케팅 확인, 거래처 연결.
- 기존 `verify-vendor-queue.cjs`, `verify-vendor-queue-conflicts.cjs`: 기존 거래처 흐름 회귀 검사.
- 변경 화면과 API를 대상으로 한 TypeScript 검사: 오류 0. 전체 프로젝트 빌드 통과를 의미하지 않는다.
- 실제 브라우저의 예시 화면: 미납 재발주 분류 후 원목록 제거, 마케팅 검토 확인 전 차단, 확인 후 분류, 새로고침과 페이지 재접속 후 이력 유지. 상단 공통 로고/버튼과 본문 여백 확인.

## 아직 검증하지 않은 범위

- Chrome에 설치된 확장 갱신과 실제 로그인 수집 → 운영 API 저장의 전체 연결은 실행하지 않았다. 코드/가상 자료 검사와 운영 연결 성공은 별개다.
- 초기 43건 기록은 모든 과거 쉽먼트 목록이 아니다. Aside가 이후 만든 출고 중 미마감 18건이나 1단계 출고 기록에 없는 건이 있는지 운영 적용 전에 확인해야 한다. 모르는 건을 완료로 간주하지 않는다.
- Aside에서 진행하던 거래처 후속 업무를 새 사이트의 수정 가능한 초안으로 모두 옮긴 상태는 아니다. 이관과 관리 화면의 최종 처리 개편은 다음 승인 범위다. 현재 원본 이력은 보존한다.
- 단종·마케팅의 누적 일괄 생성과 명시적 완료는 이후 승인에 따라 이 화면에 연결했다. 아래 추가 기록을 참고한다. 거래처 답변 뒤 재분류 관리 화면 전체는 여전히 이번 검증 범위 밖이다.
- 입고 1개는 검토 후보이며 최초 입고를 증명하지 않는다. 실제 누적 입고 확인 후 사용자가 마케팅 대상으로 확정한다.

## 후속 순서

사용자 화면 검토 → 필요한 최소 보정 → 이번 범위만 선택 커밋. 운영 반영은 별도 승인 후 진행하고, 그때 실제 확장 연결과 수집 대상 누락 여부를 확인한다. 기존 작업센터, 한진 자동화, 출력파일의 다른 미커밋 수정과 복구 폴더를 섞어 커밋하지 않는다.
