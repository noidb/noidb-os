# NOID-B 상품등록 자동화 정비안

## 목표

상품 기획부터 쿠팡 승인 SKU 반영까지를 하나의 상태 흐름으로 관리하고, 사용자는 예외 확인과 Supplier Hub 최종 업로드만 담당한다. 파일 생성만으로 등록 또는 승인대기 상태를 만들지 않는다.

## 확인된 현재 구조

1. AI 상품등록 도우미의 일괄 생성은 상품 이미지·상세 이미지·라벨·견적서를 만들고 Google 상품DB에 승인대기 행을 누적한다.
2. 라벨·견적서·상세 이미지·상품 이미지는 독립 다운로드가 가능하다. 독립 실행은 Google 상품DB를 수정하지 않는다.
3. 승인 SKU 반영은 AI 상품등록의 `등록 진행상황·상품 운영정보`에서 처리한다. Supplier Hub 전체 표 직접 전송이 기본이고, Drive/로컬 최신 XLSX 진단은 대체 경로다.
4. 신규 승인 연결은 `모델SKU | 실제옵션명`을 최우선 키로 사용한다. 기존 SKU 행은 SKU로 연결하고 상품명·발주가능상태만 갱신하며 바코드는 불변값으로 취급한다.
5. 상품공급상태 동기화는 제품DB 신규행을 만들지 않는다. S 바코드는 제외하며, 중복·충돌 행은 자동 반영에서 제외한다.
6. Supplier Hub의 `상품 등록 상태 확인(WIMS)`이 등록 진행상태의 기준이다. 상품공급상태 파일에 없다는 사실만으로 `승인대기`라고 판단할 수 없다.

## 목표 흐름

`등록준비 → 파일생성 → 업로드 전 → WIMS 등록확인 → 검수중 → 검수완료 또는 반려 → 승인 SKU 자동연결 → 운영중 → 판매중지/재등록 검토`

- `WIMS에 없음`: 파일만 생성했거나 아직 업로드하지 않은 상태. `신상승인대기`로 자동 변경하지 않는다.
- `상품 검수중`: 실제 등록이 확인된 승인대기 상태.
- `상품 검수 완료`: WIMS의 SKU·R바코드를 기존 제품DB 행에 연결할 수 있는 상태.
- `상품 등록 불가`: 반려 상태. 반려 사유를 확인하고 수정·재등록 대상으로 보낸다.
- 상품공급상태 파일: 검수완료 뒤 상품명·발주가능상태를 SKU 기준으로 지속 갱신하는 운영 자료다.

각 모델과 옵션 행에 상태, 마지막 확인일, 원본 파일, 매칭 규칙, 예외 사유를 남긴다. 파일명이나 상품명 유사도는 보조 증거로만 사용하고 모델SKU와 SKU를 기본 키로 삼는다.

## 구현 순서

### 1단계: 등록 작업 단순화

- 일괄 생성과 개별 파일 생성을 명확히 분리한다.
- 라벨은 모델명·제조연월·제조자명·수입자명을 현재값으로 미리 채우고 `상품이미지DB/라벨`에 단독 저장한다.
- 일괄 생성 전 결과 파일과 Google 상품DB 변경 행을 한 화면에서 미리 보여준다.
- 생성 성공, 로컬 저장 성공, Google Sheet 반영 성공을 서로 다른 상태로 표시한다.

### 2단계: WIMS 등록상태 수집

- WIMS의 상품명·모델SKU·견적서 ID·상태·SKU·R바코드를 등록 이력으로 저장한다.
- WIMS에 없는 파일생성 건은 `업로드 전`, `상품 등록 불가`는 `반려`, `상품 검수중`은 `승인대기`, `상품 검수 완료`는 `승인완료`로 분류한다.
- WIMS는 로그인 화면이라 서버가 직접 읽는 구조로 가정하지 않는다. 브라우저에서 열린 목록을 사용자가 한 번 전송하는 보조 수집 방식 또는 Supplier Hub가 제공하는 다운로드 파일을 우선 검토한다.
- WIMS 근거가 없는 행은 제품DB 상태·SKU·바코드를 자동 변경하지 않는다.
- 일부 페이지나 검색 결과만 수집한 경우, 제품DB 행이 보이지 않는다는 이유로 `WIMS에 없음`을 확정하지 않고 `수집 범위에서 미확인`으로 표시한다. 전체 검색 결과 또는 모델SKU 직접 검색 결과가 있어야 미등록을 확정한다.

### 3단계: 승인 SKU 동기화 단일화

- AI 상품등록의 `등록 진행상황·상품 운영정보`를 유일한 운영 진입점으로 정한다. 작업센터는 발주서·입고·피킹 업무만 유지한다.
- Supplier Hub 확장 기능으로 상품공급상태 전체 페이지를 직접 전달하고, 전체 건수·페이지·필수 열·중복 SKU 검증에 통과한 자료만 진단한다.
- 최신 XLSX 자동 탐색은 확장 기능을 쓸 수 없을 때의 대체 경로로 유지한다.
- S 바코드 제외, 신규행 0건, 변경 셀 미리보기, 전체 시트 백업, 원자적 반영을 유지한다.
- 결과를 `자동연결 / 등록상태 확인 필요 / 중복 / 충돌 / 기존 SKU 갱신` 다섯 묶음으로 보여준다.

### 4단계: 매칭과 예외 자동화

- 신규 SKU: 명시 모델SKU 완전일치 → 옵션 완전일치 → 정규화 상품명 점수 순으로 후보를 만든다.
- SKU가 이미 있는 행: SKU 완전일치만 허용하고 상품명·발주가능상태를 갱신한다. 바코드는 불변값으로 취급하며 다운로드 값이 다르면 자동 수정하지 않고 충돌로 보고한다.
- 동일 다운로드 SKU가 여러 제품DB 행에 연결되거나 후보가 복수이면 전체 자동 반영에서 제외한다.
- 실제 WIMS 검수중 행에만 `마지막 확인일`과 `다음 확인 권장일`을 남겨 같은 항목을 반복 확인하는 일을 줄인다.

### 5단계: 사용하지 않는 기능 정리

- `기존 SKU 연결`은 최근 사용 여부와 성공 사례를 먼저 기록한다.
- 사용하지 않는 것이 확인되면 화면에서 숨기고, 한 배포 주기 동안 데이터·API는 유지한다.
- 문제가 없을 때만 Apps Script의 구형 연결 함수와 중복 UI를 삭제한다. 제품DB 기존행이나 SKU 교체이력은 삭제하지 않는다.

## 사람에게 남길 일

- Supplier Hub의 외부 제출 직전 파일 확인과 최종 등록 실행
- 중복 후보 또는 바코드 충돌 검토
- 판매중지 SKU의 삭제/재등록 결정
- 배포 및 실제 외부 제출 최종 승인

## 완료 기준

- 제품DB 신규행 생성 0건
- S 바코드 반영 0건
- 같은 SKU의 복수 행 배정 0건
- WIMS에 없는 행을 승인대기로 표시하는 건 0건
- WIMS 반려 행에 SKU·바코드를 자동 반영하는 건 0건
- 자동 반영 결과에 원본 파일명·행번호·매칭 규칙·변경 전후값 기록
- 라벨 단독 작업이 다른 파일 생성이나 Google Sheet 쓰기를 유발하지 않음
- 실패 시 일부 반영 없이 전체 차단하고 재실행 가능한 미리보기 제공
