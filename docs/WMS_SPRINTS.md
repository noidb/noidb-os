## Sprint 1 — 발주서 데이터 & 작업센터 기반

가장 먼저 구현할 후보:

1. **발주서(PurchaseOrder) 조회 화면**
   - 발주서 번호 기준으로 목록/상세 조회
   - `originalExpectedDate`/`currentExpectedDate`, `originalFulfillmentCenter`/`currentFulfillmentCenter` 표시
2. **작업센터(Work Center) 기초 골격**
   - 발주서 출력 탭을 대체할 화면의 최소 버전(선택 → 목록 표시)
3. **위치 계층(선반 → 박스 → 모델 → SKU) 기준 데이터 조회**
   - 실제 창고 위치 데이터를 읽어와 트리 형태로 표시

이 스프린트는 "읽기 전용 조회" 범위로 한정해 리스크를 최소화하는 것을 권장한다.

### Sprint 1.5 — 서플라이어 허브 실제 발주 읽기 전용 연동 (2026-08-18 완료)

목표: 샘플 데이터 대신, 쿠팡 서플라이허브의 실제 신규 발주서를 읽기 전용으로 가져와
`/wms/work-center`에 정확히 표시한다. 서플라이어 허브 데이터는 조회/캡처만 하고 절대 수정/제출하지
않는다.

- 시도했으나 불가능했던 방법: claude-in-chrome으로 `supplier.coupang.com`을 실시간 조회하려 했으나,
  (1) 확장 프로그램 자체가 이 도메인을 "안전 제한"으로 차단했고, (2) 사용자가 직접 연 탭은 자동화
  탭 그룹 밖이라 접근 불가 — 이번 스프린트에서는 이 방식을 포기했다.
- 실제로 채택한 방법: 사용자가 서플라이어 허브에서 직접 다운로드한 "발주서리스트_*.xlsx" 원본
  엑셀 파일을 `lib/wms/data/incoming-purchase-orders/`(Git 추적 제외) 폴더에 넣으면,
  `lib/wms/supplier-hub-orders.ts`가 매 요청마다 그 폴더의 모든 `.xlsx`를 읽기 전용으로 파싱해
  `/api/wms/supplier-hub-orders`(GET만 존재)로 제공하고, `/wms/work-center`가 이를 화면에 표시한다.
- **최종 목표(아직 미구현)는 다운로드 없이 서플라이어 허브 화면을 NOID-B OS가 직접 읽는 구조**다.
  캡처 방식(파일 배치 → 향후 실시간 화면 읽기)만 교체될 뿐, `SupplierHubPurchaseOrder` 데이터 형태와
  API 응답 형태는 그대로 유지하도록 설계했으므로 `loadSupplierHubPurchaseOrders()` 내부 구현만
  교체하면 된다.
- 기존 샘플 기반 피킹 카드/흐름(`picking-sample-data.ts`, `picking-flow-context.tsx`)은 이번
  스프린트에서 변경하지 않았다 — 실제 발주 표시는 별도 섹션으로 병행 표시.

## Sprint 2 — 피킹 흐름

**운영 원칙 (2026-08-18 사용자 확정 — 구현 전 반드시 준수)**:

- 피킹은 쉽먼트별로 따로 하지 않는다. 여러 쉽먼트의 SKU를 합쳐 **구역 → 선반 → BOX → 모델 → SKU**
  순서로 통합 피킹한다. 목표는 전체 작업 중 **같은 BOX를 한 번만 여는 것**.
- 피킹 화면에서는 SKU마다 "총 찾을 수량"과 "쉽먼트별 분배 수량(바구니/카트 번호 + 쉽먼트 번호 +
  수량)"을 함께 표시한다.
  예: 총 7개 찾기 → 바구니1/SH-001→2개, 바구니3/SH-003→4개, 바구니5/SH-005→1개
- **포장과 출력만** 쉽먼트별로 분리한다: 분류=쉽먼트별 바구니, 포장=쉽먼트별, 출력=쉽먼트별
  피킹리스트·송장·상품 바코드·BOX 라벨·거래명세서 5종 세트. 같은 BOX를 쉽먼트별로 반복해서 열지
  않는 것이 핵심.
- 관련 타입은 `lib/wms/types.ts`의 `Shipment.shipmentNumber`, `PickingItemShipmentAllocation`에
  미리 정의해두었다 (Sprint 1.5에서 추가, 구현은 이 스프린트에서).

구현 항목:

1. 통합 피킹 리스트 생성 (여러 쉽먼트 SKU 합산 → 구역/선반/BOX 단위 정렬, BOX 1회 오픈)
2. SKU 옵션 이미지 매칭 표시
3. 전량찾음 / 부분찾음 / 현재고 입력 UI 및 상태 저장 + 쉽먼트별 바구니 분배 입력/표시
4. 부족 수량 → 거래처발주 초안 자동 생성 로직
5. 쉽먼트별 포장 분류 화면, 쉽먼트별 출력 5종 세트(피킹리스트/송장/상품 바코드/BOX 라벨/거래명세서)

## 우선순위 판단 기준

- 사용자 승인이 필요한 흐름(거래처발주 발송, 서플라이어 허브 반영)은
  반드시 승인 UI가 먼저 갖춰진 뒤에 자동화한다.
- 외부 시스템(서플라이어 허브, 구글시트) 연동은 읽기 → 쓰기 순으로 리스크를 낮춰가며 확장한다.
- 신규 발주 자동 감지(브라우저 자동화)는 가장 리스크가 높으므로 마지막 단계로 미룬다.
