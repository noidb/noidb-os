# NOID WMS 마스터 플랜

## 1. 목적

기존 NOID-B OS(상품등록 자동화)는 그대로 유지하면서, 별도의 창고/발주/피킹 관리 시스템(NOID WMS)을
같은 프로젝트 안에 독립적으로 추가한다. 두 기능은 라우트와 컴포넌트 레벨에서 완전히 분리하며,
서로의 코드를 공유하지 않는 것을 기본 원칙으로 한다.

## 2. 기존 기능과의 관계

- 상품등록 자동화(`app/page.tsx`, `app/api/*`, `lib/excel/*`, `lib/product-db/*`)는 **변경하지 않는다.**
- WMS는 `app/wms/*` 하위에 신규 라우트로 추가한다.
- 구글시트는 두 시스템이 공유하는 **기존 데이터 저장소이자 백업 수단**으로 유지한다.
  - WMS도 구글시트를 진실 공급원(source of truth) 또는 백업 대상으로 사용할 수 있으나,
    상품등록 자동화가 사용하는 시트/시트 구조는 건드리지 않는다.
- 최종적으로 직원은 별도 툴 없이 **사이트(웹)만** 사용해 WMS 업무를 처리한다.

## 3. WMS 핵심 업무 흐름

1. **발주서(PurchaseOrder) 관리**
   - 발주서의 고유값은 **발주서 번호(purchaseOrderNumber)** 이다.
   - 같은 발주서 번호 내에서는 SKU 구성과 수량이 변경되지 않는다.
   - 변경 가능한 값은 **입고예정일**과 **물류센터(물류창고)** 뿐이다.
   - 이 변경은 사용자 승인 후 서플라이어 허브(외부 시스템)에 자동으로 요청되며,
     승인/거부 결과는 시스템이 자동 감지한다.

2. **발주서 출력 / 작업센터**
   - 현재는 발주서를 출력하는 탭으로 시작하되, 이후 스프린트에서
     "작업센터(Work Center)"로 대체되어 발주서 기반 작업 배치(WorkBatch) 생성/관리로 확장된다.

3. **위치 구조**
   - 창고 내 위치 계층은 **선반(Shelf) → 보관박스(Box) → 모델(Model) → SKU** 순서로 구성된다.
   - 모든 재고/피킹/입고 데이터는 이 계층 구조를 기준으로 위치를 식별한다.

4. **피킹(Picking)**
   - 피킹 동선은 **같은 박스를 한 번만 열도록** 박스 단위로 정렬된 작업 리스트를 제공한다.
   - 각 피킹 항목은 정확한 SKU 옵션 이미지를 함께 표시해 오피킹을 방지한다.
   - 결과 입력은 다음 3가지를 지원한다.
     - 전량찾음(전체 수량 확보)
     - 부분찾음(일부만 확보, 부족 수량 발생)
     - 현재고 입력(실사 재고 수량 직접 입력)
   - 부족 수량이 발생하면 **거래처발주(VendorOrder)**로 자동 연결된다.

5. **거래처 발주(VendorOrder)**
   - 피킹 부족분으로 자동 생성되며, **사용자 승인 후에만 실제 발송**된다.
   - 승인 전까지는 초안 상태로 보관된다.

6. **입고(Inbound) 및 쉽먼트(Shipment)**
   - 입고예정일/물류센터 변경은 승인 절차를 거쳐 서플라이어 허브에 자동 반영을 요청한다.
   - 쉽먼트가 생성되면, 웹에서 생성되는 거래명세서와 라벨 PDF를 **자동으로 다운로드 및 출력**한다.

7. **신규 발주 감지**
   - 신규 발주 자동 감지는 이번 기반 작업 범위에 포함하지 않으며,
     추후 스프린트에서 브라우저 자동화(예: 페이지 폴링/스크래핑) 방식으로 구현 예정이다.

## 4. 설계 원칙

- **격리 우선**: WMS 코드는 기존 상품등록 코드와 디렉토리/라우트 수준에서 분리한다.
- **점진적 확장**: 지금 단계는 라우트 뼈대와 타입 정의만 만들고, 실제 로직/DB 연동은 다음 스프린트에서 진행한다.
- **승인 기반 변경**: 외부 시스템(서플라이어 허브)에 영향을 주는 변경(입고예정일, 물류센터, 거래처발주)은
  반드시 사용자 승인 단계를 거친다.
- **불변값 보호**: 발주서 번호, SKU, 수량처럼 한 번 확정되면 안 되는 값은 타입 레벨에서부터
  원본값(original*)과 현재값(current*)을 분리해 추적한다.
