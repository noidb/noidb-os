# 계획서: 제품DB 하나로 합치기 (2026-09-22)

작성: Claude Code · 상태: **계획만 작성함. 시트·코드는 아직 아무것도 바꾸지 않음**

## 0. 목표 (한 줄씩)

1. `노이드비 상품DB` → `제품DB` 탭 하나만 기준으로 쓴다. 연결표 시트와 통합 엑셀은 보관용으로만 둔다.
2. 재등록 목록·재등록 저장·사진 검색이 모두 **제품DB의 열**만 보게 한다.
3. 기존 값은 지우거나 바꾸지 않는다. **새 열과 새 행만 추가**하고, 확인된 2행만 고친다.

## 1. 시작 전에 꼭 알아야 할 위험 (새로 발견)

### 1-1. 운영 스크립트는 PC의 원본과 다른 버전이다 (2026-09-22 읽기 확인)

| | 운영 Apps Script ('DB자동입력', 상품DB에 연결됨) | PC 원본 `templates/구글시트_상품DB_연동.gs` |
|---|---|---|
| 길이 | 3,266줄 | 2,990줄 |
| 제품DB 열 목록 | 34개. **실제 제품DB 1~34열과 정확히 같음** | 36개 (재고현황·제조국명 포함). 실제 시트와 다름 |
| 쿠팡 추출DB 반영 기능 | **없음** | 있음 |
| 재등록 '패키지' 검사 | 제품DB '패키지' 열에 **무엇이든 적혀 있으면** 막음 | 상품명에 세트·패키지·랜덤발송이 있으면 막음 |

- 실제 제품DB 열: 1~34열은 운영 스크립트 목록과 같다. 그 뒤로 **35열 제조국명, 36열 이전창고번호**가 스크립트가 모르는 열로 붙어 있다.
- **PC 원본을 그대로 운영에 붙여넣으면 안 된다.** 열 목록이 달라서 제품DB 열을 다시 배치하고, 이전창고번호 같은 열이 지워질 수 있다. 스크립트 수정은 반드시 **운영 버전을 기준**으로 한다.
- 앞서 걱정했던 두 가지('쿠팡 추출DB 업데이트'가 엉뚱한 열에 쓰는 문제, 새 상품 저장 때 열이 지워지는 문제)는 **운영에서는 해당하지 않는다.** 운영 스크립트의 열 목록이 실제 시트와 맞고, 추출DB 반영 기능은 운영에 없다.
- 세트·패키지·랜덤발송 이름 때문에 막히는 일은 **운영에는 없다.** 재등록 목록 56개 중 운영에서 막히는 것은 **wb011852 1개**다. '패키지' 열에 "무"(= 패키지 없음)라고 적혀 있는데도 막힌다.

### 1-2. 새로 찾은 위험: 정렬 기능이 왼쪽 34개 열만 옮긴다

- 운영 스크립트의 제품DB 정렬 기능(`sortProductDbDefault_`)은 **1~34열만 정렬**한다. 모델별 행 교체, 일괄 쓰기 등 여러 곳에서 호출된다.
- 그래서 정렬이 일어나면 줄은 움직이는데 **35열 이후(제조국명, 이전창고번호)는 제자리에 남는다.** 그러면 다른 상품의 줄에 붙게 된다.
- 확인 결과(2026-09-22) **제조국명은 아직 어긋나지 않았다.** 2,667행 전부 통합 엑셀의 원산지와 SKU별로 일치한다. 다만 정렬이 한 번이라도 일어나면 어긋날 수 있다.
- 새 열(제품코드 등)을 지금 상태로 맨 오른쪽에 추가하면 **같은 식으로 어긋난다.** 그래서 **정렬을 전체 열 기준으로 고친 뒤에만** 새 열을 추가한다.

**→ 지금 당장 지킬 것**
- 없음. 평소 쓰던 기능은 그대로 써도 된다. 다만 **제품DB에 직접 새 열을 추가하지 않는다.**

## 2. 무엇을 바꾸나

### 2-1. 제품DB에 새 열 4개 (맨 오른쪽 끝, 이전창고번호 뒤)

| 새 열 | 채우는 값 | 출처 |
|---|---|---|
| `제품코드` | P00001 형식. 한 번 정하면 바꾸지 않음 | 연결표 `10_SKU조회` (SKU ID로 연결) |
| `재등록구분` | 1차_판매중지 / 2차_판매량저조영구정지 / 영구제외_가품 / 영구제외_금은시세 / 빈칸 | 연결표 `10_SKU조회` |
| `사진폴더(확정)` | 사진 폴더 경로 | 연결표 `10_SKU조회` |
| `정리메모` | 예: "엑셀에서 추가 0922", "테스트 복구 0922" | 이번 작업에서 기록 |

- 기존 36개 열은 **위치도 값도 바꾸지 않는다.**
- 겹치는 SKU **2,656개**는 SKU ID로 값을 붙인다.
- 제품DB에만 있는 새 승인 SKU 9개(mn000008, wn011365, wn00272, wn00266)는 같은 모델명의 제품코드를 이어받는다.
- 기존 `현재상태`(판매중지·과재고 등 직접 적은 표시)는 그대로 둔다. 재등록 판단은 새 `재등록구분` 열로 한다.

- 목록에서 빠지는 것: 가품 3개(mb011243, wn00591, wa000271), 이미 재등록을 마친 wr011699.
- **세트·패키지·랜덤발송 18개도 일반 상품처럼 재등록할 수 있게 한다** (사용자 결정 2026-09-22).

## 3. 코드 변경

### 3-1. 구글시트 스크립트 (Apps Script, 배포 승인 필요)
**기준은 운영 버전.** 먼저 운영 코드를 저장소에 새 파일로 옮겨 둔다. PC 원본은 덮어쓰지 않는다.
1. 정렬 기능이 **제품DB 전체 열**(마지막 열까지)을 함께 옮기게 한다. 새 열을 추가하기 전에 반드시 먼저 한다.
2. 열 재배치 기능이 **모르는 열(제조국명, 이전창고번호, 새 열 4개)을 절대 지우지 않게** 한다.
3. 재등록 저장 허용 조건: `재등록구분`이 1차 또는 2차일 때. 영구제외는 막는다.
4. '패키지' 열 검사는 뺀다. 세트·패키지·랜덤발송도 일반 상품처럼 재등록한다(사용자 결정). "무"가 적혀 막히던 wb011852도 풀린다.
5. 운영 스크립트는 **모든 옵션이 판매중지일 때만** 재등록을 허용하고 있었다. 그래서 일부 옵션만 판매중지인 8개 모델(we011889, ws011369, we011313, we00577, we00486, wb00385, wb00367, wb00182)이 막혀 있었다. 규칙대로 **옵션 하나라도 판매중지면 모델 전체 허용**으로 고친다.
6. 제품DB의 필터(정렬 버튼) 범위도 전체 열로 넓힌다. 시트에서 직접 정렬할 때 오른쪽 열이 어긋나지 않게 하기 위해서다.
7. 열 목록이 달라도 제품DB를 자동으로 재배치하지 않는다. 대신 오류로 멈춘다(데이터 보호).

### 3-2. 사이트 (커밋·배포 승인 필요)
1. 등록도우미: 재등록일 때 **모델명·모델번호 잠금**(AI 분석이나 카테고리 변경으로 바뀌지 않게), '기존상품 재등록 SKU ID' 칸 숨기기.
2. 연결 대장: 재등록 목록을 `재등록구분` 열로 만든다(1차/2차 표시). 사진 폴더는 제품DB의 `사진폴더(확정)` 열에서 읽는다.
3. 메인: AI 상품등록 도우미 맨 위에 [재등록 대상·사진 고르기] 버튼 추가. 연결 대장의 돌아가기 링크는 AI 상품등록으로 바꾼다.
